PUMBA BOARD

Канбан-доска в терминале для задач ИИ-агентов

Вы ведёте задачи на доске, а агент берёт карточку, проходит по колонкам и двигает её сам. Всё хранится в папке .pumba/ рядом с кодом.

cargo install --path .
Быстрый старт GitHub

Что это

Pumba Board - программа для терминала на Rust, бинарник называется pumba. Вы заводите карточки и настраиваете колонки, а ИИ-агент выполняет работу по этим карточкам.

Всё в одной папке

Колонки и правила лежат в .pumba/board.json, карточки в .pumba/tasks/, инструкции для агентов в .pumba/AGENTS.md. Это обычные файлы, их видно в git.

Порядок задаёте вы

У каждой колонки три части правила: «Перед работой», «Работа», «После работы». Что делать с карточкой, решает доска, а не программа.

Пять инструментов

Claude Code, Codex, Cursor, Copilot и OpenCode. Одна команда ставит им агентов и скиллы.

След остаётся

Агент записывает краткие решения в раздел «Ход работы» карточки. Удалённые карточки уходят в корзину, файл остаётся на диске.

Быстрый старт

  1. Установите из исходников

    cargo install --path .

    Нужен Rust. Крейт называется pumba-board, бинарник pumba.

  2. Откройте доску в папке проекта

    pumba

    Если .pumba/ нет, программа предложит её создать и выбрать инструменты для агентов.

  3. Или создайте доску из командной строки

    pumba init

    Создаёт .pumba/ и ставит агентов и скиллы. Флаг --no-agents создаёт только папку.

  4. Поставьте агентов для нужных инструментов

    pumba install --tools claude,codex,cursor,copilot,opencode

    Существующие файлы не перезаписываются, для этого нужен --force. Вместо списка можно написать all.

  5. Скажите агенту, что делать

    выполни задачу T-001
    /pumba-task T-001

    Задачу берёт скилл pumba-task. Можно сказать и «возьми эпик E-001».

Как устроена доска

Колонки по умолчанию образуют цепочку. Агент ведёт карточку от колонки к колонке, пока не дойдёт до колонки, где нужен человек.

  1. ● Бэклог
  3. ● В работе
  5. ● На ревью
  7. ● Готово
  8. ● Ждёт разработчика

Неудача после всех попыток уводит карточку в «Ждёт разработчика».

Три части правила колонки

1

Перед работой

Условия старта: что проверить, о чём спросить, когда остановиться. Агент выполняет это раньше всего.

2

Работа

Что делает исполнитель колонки, пока карточка в ней: например, план, тесты и реализация.

3

После работы

Как проверить результат, что делать при неудаче и куда перенести карточку.

Кроме правила, у колонки есть агент (субагент, который делает работу), следующая колонка (после успеха), цвет и название. Первая и последняя колонки закреплены: их нельзя двигать и удалять. Новые колонки встают перед последней.

КолонкаЧто происходит
БэклогАгент спрашивает: «брать в работу?». После «да» карточка идёт в «В работе».
В работеИсполнитель pumba-worker: план, тесты, реализация, проверки. Дальше «На ревью».
На ревьюИсполнитель pumba-reviewer: приёмка и ревью. После одобрения один коммит и «Готово».
Ждёт разработчикаАгент остановился и ждёт решения человека. Решение есть - карточка возвращается в «В работе».
ГотовоТолько последняя колонка снимает блокировку с зависимых карточек.

Карточки

Карточка - один файл .pumba/tasks/<ID>.md: заголовок в frontmatter и описание для агента в Markdown. Номер совпадает с именем файла.

Эпик и задача

Эпик (E-001) собирает задачи (T-001). Связь хранится в поле parent задачи, у эпика на доске виден прогресс.

Модель и уровень размышления

Подсказка агенту, какую модель и какой уровень рассуждений взять. Списки настраиваются клавишей M.

Спринт

p добавляет карточку в текущий спринт, s показывает только его, ] начинает следующий: незавершённые карточки перейдут в него.

Зависимости и «Блокирует»

Поле «Зависит от» и обратное «Блокирует». Пока зависимости не в последней колонке, карточка заблокирована, и агент откажется её брать.

Скрытие

x прячет карточку с доски, v показывает скрытые.

Корзина вместо удаления

d отправляет карточку в корзину: файл остаётся на диске. Восстановить можно в корзине (B). Её номер больше не используется.

Ссылки @путь в описании подставляются подсказкой. Агент прочитает эти файлы перед работой.

Правила проекта

Клавиша P открывает правила: шесть переключателей и поле для своих правил в Markdown. Из них и из правил колонок программа собирает .pumba/AGENTS.md и переписывает файл при каждом изменении. Агент читает его первым.

Стиль коммитов
Conventional Commits, Gitmoji, префикс с ID задачи, свободный формат
Модель ветвления
GitHub Flow, Git Flow, Trunk-based, ветка на задачу
Стратегия слияния
Squash, merge-коммит, rebase
Тестирование
Тесты обязательны, TDD, тесты по желанию
Автономность
Сначала спрашивать перед крупными изменениями, работать автономно
Обновление доски
Агент двигает задачи, вручную (агент предлагает, вы отвечаете)

Жирным выделен вариант по умолчанию.

Как работает агент

Агенту хватает фразы «выполни задачу T-001». Дальше работает скилл pumba-task: он ведёт карточку по колонкам.

  1. 1

    Принимает карточку

    Читает файл и проверяет зависимости. Если хоть одна не в последней колонке, агент отказывается и называет блокирующие карточки.

  2. 2

    Читает правила

    Берёт «Правила проекта» из AGENTS.md и правило колонки карточки из board.json.

  3. 3

    Перед работой

    Проверяет условия, предупреждает, спрашивает. Правило велит остановиться - агент останавливается.

  4. 4

    Работа

    Запускает субагента колонки, например pumba-worker, или делает работу сам, если исполнителя нет.

  5. 5

    После работы

    Проверяет результат: запускает проверки, читает итог исполнителя. При неудаче повторяет на модели выше (haiku, sonnet, opus), потом зовёт человека.

  6. 6

    Двигает карточку

    Меняет строку column: в файле и идёт дальше, пока не упрётся в колонку без следующей.

  7. 7

    Оставляет след

    Пишет 1-3 строки в «Ход работы» карточки и отчитывается: что сделано, какой коммит, какие карточки разблокированы.

Пять субагентов

pumba-planner
план задачи или порядок карточек эпика, только чтение
pumba-tester
тесты до реализации, приёмка, разбор упавших проверок
pumba-worker
реализация по плану
pumba-reviewer
ревью с серьёзностью замечаний, только чтение
pumba-committer
один коммит по правилу «Стиль коммитов»

Субагентов запускает только основная сессия, исполнители никого не вызывают. Второй скилл, pumba-new-card, создаёт карточку с правильным номером и frontmatter по вашей просьбе.

Агент не удаляет карточки, не правит board.json и AGENTS.md, не делает push и слияние без прямой просьбы.
